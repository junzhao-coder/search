# 滚动复盘流程（S7 经营验证）

> 目的：在**用户真实执行**经营操作的前提下，按固定节奏记录、导出、核算与复盘，形成可追溯的结论（当前为**暂未验证盈利**）。
> 本流程**不自动化任何经营动作**（发布/联系/采购/付款），也**不自动生成数字**；所有数据由用户提供并附证据。
> 未实现能力如实标注：定时触发/提醒/实际利润自动核算/报表/告警/自动对账均未实现，需人工执行。

## 1. 节奏（频率待用户裁定）

| 节奏 | 动作 | 产出 |
| --- | --- | --- |
| **事件即时** | 用户执行经营动作后，按 `OPERATING_LOG_TEMPLATE.md` 追加一行（含证据路径、`user_confirmed=yes`） | `docs/s7/runs/<YYYY-MM-DD>/operating_log.csv` 追加行 |
| **每日（可选）** | 导出当日摘要（只读），核对候选与证据 | `reports/s7-<YYYY-MM-DD>/daily-<date>.json/.csv` |
| **每周（建议）** | 汇总本周成交/退款/支出/人工，计算单位利润等指标，更新状态文件 | `docs/s7/runs/<YYYY-MM-DD>/review-<week>.md` + 更新 `CURRENT_STATUS.md` |
| **止损触发** | 命中用户确认的预算/亏损/售后条件时立即暂停经营并复盘 | `docs/s7/runs/<YYYY-MM-DD>/stop-review.md` |

> **频率、预算上限、观察窗口、止损条件均为用户裁定项**（当前未设定，本流程不预设数值）；用户确认后写入 `CURRENT_STATUS.md` 的"试验参数"节。

## 2. 每次复盘步骤

### 步骤 1：记录与核对（用户主导）
- 打开 `OPERATING_LOG_TEMPLATE.csv` 复制为本次 run 的 `operating_log.csv`；按模板逐条补录（真实、附证据、用户确认）。
- 核对：`sale` 订单号唯一；`refund` 有 `related_log_id` 指向原成交；未知费用留空并说明；金额均为整数分。
- 确认候选 `candidate_id` 存在且为 `data_origin='real'`（真实数据才计入经营验证）。

### 步骤 2：导出只读摘要（系统只读能力）
```powershell
# 只读复用 daily_digest；默认只统计 real；--as-of 必填（UTC 秒精度）
& .\.venv\Scripts\python.exe tools\export_daily.py --db instance\app.db `
    --as-of <YYYY-MM-DD>T00:00:00Z --limit 5 --out-dir reports\s7-<YYYY-MM-DD>
```
- 产物：`daily-<date>.json`（每日摘要原样）与 `daily-<date>.csv`（top/blocked/observing/exploring 四池，9 列）。
- 说明：摘要只展示候选/排序/情景，**不含成交与利润**；订单与利润以 `operating_log.csv` 为准。
- 若业务库没有 real 数据，导出为空（计数 0）——这是真实状态，不得用合成数据补足。

### 步骤 3：手工核算（用户/复盘者，按模板 §3）
- 对每条成交计算 `actual_net_per_order_minor`＝收入 − 采购 − 平台费 − 支付费 − 获客分摊 − 退款/售后 − 人工 − 其它；可为负。
- 汇总本周/本期指标（口径见 §3）：成交笔数、收入合计、成本合计、净利合计、单位利润、每小时收益、退款/售后负担、供应稳定性（是否有足够可复用货源）。
- **未知项单列**，不得按 0 处理；不得估算冒充实际。

### 步骤 4：更新当前状态
- 在 `CURRENT_STATUS.md` 更新：数据条数、统计区间、净利结论、限制与下一步。
- 结论只有三种：**暂未验证盈利** / **本期亏损** / **本期盈利（需注明样本量与区间）**；不得只写"本期盈利"而不给区间与样本量。

### 步骤 5：复盘会议（用户 + 策划者）
按 DEVELOPMENT_PLAN §11 的分支讨论：
- 证据充分但**无询单** → 检查需求真实性/标题/价格/曝光，不放大投入；
- 有询单但**无成交** → 检查报价/信任/交付方式；
- 成交后**售后/退款高** → 检查品类与交付负担，必要时停做；
- 合格商品不足 → 按实际数量开展或继续补证，**不为试卖放宽四项门槛**。
- 决策：继续 / 缩小范围 / 暂停 / 补充证据；每次决策记录理由与证据引用。

### 步骤 6：留证与归档
- `docs/s7/runs/<YYYY-MM-DD>/` 内至少包含：`operating_log.csv`、`review-<week>.md`、`evidence/`、以及本次导出的摘要文件（可复制）；
- 证据不含账号密码、支付凭证全文等敏感信息；对外引用需用户确认（`user_confirmed=yes`）；
- 历史 run 不覆盖、不改写；更正在新 run 中追加说明。

## 3. 指标定义（手工，当前未自动化）

| 指标 | 定义 | 依赖数据 | 当前实现 |
| --- | --- | --- | --- |
| 单位利润（单笔） | `actual_net_per_order_minor`（见模板 §3） | 成交行的收入与各成本列 | 手工 |
| 每小时收益 | 期间净利合计 ÷ 期间人工分钟合计 × 60 | 成交行 + `manual_time` | 手工 |
| 退款/售后负担 | 退款金额合计 ÷ 成交金额合计；另记退款笔数占比 | `refund` 行与成交行 | 手工 |
| 供应稳定性 | 同款可复用货源数、补货时长（人工判断并注明依据） | 货源页/证据 | 手工 |
| 样本量与区间 | 成交笔数、统计起止日期、候选数 | `operating_log.csv` | 手工 |

> 以上指标**不是**系统已有报表；系统仅提供只读每日摘要导出。任何自动化/报表/提醒均未实现。

## 4. 防伪与审计规则

- 每个对外引用数字必须能回溯到：`log_id` + `evidence_path` + `user_confirmed=yes`；缺一不计入结论。
- 禁止：合成数据、示例数据、模型输出、估算、占位符、事后补造订单/金额/截图。
- 禁止把"预测利润"当作"实际利润"；预测快照只在系统中留痕，不进入经营验证结论。
- 发现错误：新增加更正行并注明原 `log_id`；汇总用更正后的有效行，保留历史。

## 5. 失败与止损处理

- 预算耗尽、连续亏损、售后超预期、平台风控/封禁、货源断供等，按用户确认的止损条件**立即暂停**对外动作；
- 暂停后执行一次"止损复盘"：记录触发条件、已发生订单/退款、损失金额、已停止动作；不改写历史数据；
- 恢复经营须用户重新确认；系统侧无需改代码（本流程为文档与人工操作）。

## 6. 与系统能力的关系（如实）

| 环节 | 系统支持 | 仍需人工 |
| --- | --- | --- |
| 候选/证据/成本/门槛 | 导入与只读展示（已实现） | 真实数据采集与确认 |
| 每日摘要 | 只读导出/HTTP（已实现，默认 real-only） | 判断与复盘 |
| 经营事件记录 | `feedback` API 可记录事件/预测快照（已实现） | 实际利润手工核算、证据整理 |
| 备份/恢复 | 脚本已实现（未实现契约端点） | 定期执行与保管 |
| 定时触发/提醒/自动发布/联系/采购/付款/实际利润报表 | **未实现** | 全部人工 |
