# 发布后回填与反馈记录卡

> 用途：发布后把链接/时间记回工作台，并按同一口径记录经营数据，方便一周后复盘。
> **数据只记不发**：这张卡只写进你自己的本地文件；**不向买家索取任何信息**，**不在聊天里要账号/密码/验证码**。

---

## 一、回填工作台（3 分钟）

1. 打开 `/copy?wo=<你的单号>` → 滚到「**发布回填**」区。
   **你应该看到什么**：状态选择（未发布/已发布/已下架）、发布链接、发布时间、已售数量、平台备注。
2. 状态选 **已发布**；**发布链接**粘贴完整商品 URL（必须以 `http://` 或 `https://` 开头，否则保存会提示格式错误）。
   **你应该看到什么**：保存后页面显示「当前状态：已发布」+ 链接 + 更新时间。
3. **发布时间**填你实际点发布的时间（文本即可，建议 `2026-10-24T20:30:00Z` 这种格式，便于排序）。
4. **平台备注**写类目路径与审核情况（例：`学习/办公→文档模板；审核通过`）。
5. **已售数量**填当前成交数；**没成交就填 0**（不要留空，不要填 1 充数）。
6. 点「保存发布信息」。
   **你应该看到什么**：绿色提示消失、状态徽章变「已发布」；若之前记录过导出，会出现“发布信息已变更，建议重核就绪并重新导出”——点一次「记录本次导出」即可。

---

## 二、C3 反馈字段（每个商品单独记一行）

> 表就放在 **`docs/validation/product-workflow/b25/feedback-log.csv`**（**只此一份**，不要在 b24 另存副本）。填完直接跑 `python review.py feedback-log.csv` 看 4 个数字与一条建议——三步说明与阈值见 [b25/README.md](../b25/README.md)。字段如下。

**直接复制这两行**（第一行表头、第二行是 synthetic 示例，改成你自己的数据）：

```csv
日期,单号,渠道,曝光,询单,成交,退款,实际售价,到手,人工耗时分钟,交付方式,备注
2026-10-24,wo:20261024-00000000,xianyu,na,4,1,0,19.9,18.5,45,站内文件,synthetic 示例，不是真实经营数据
```

> 英文表头也能跑（自动映射：`date→日期`、`orders→成交`、`manual_minutes→人工耗时分钟` 等，见 `b25/README.md` 的映射表）；
> 英文列名拼错时，脚本会打印「检测到的表头 / 期望的表头（可直接复制）/ 修正建议」，照抄那行表头即可。

| 字段 | 怎么填 | 口径 / 注意 |
| --- | --- | --- |
| 日期 | `2026-10-24` | 记录当天日期（UTC 或本地都行，保持统一） |
| 单号 | `wo:2026xxxx-xxxxxxxx` | 工作台单号，便于追溯 |
| 渠道 | `xianyu` | 只记实际发布平台 |
| 曝光/浏览 | 平台给的浏览数；没有就写 `na` | **不要估算**；平台不显示就写 `na` |
| 询单数 | 主动来问的人数 | 同一个买家多次问算 1 |
| 成交数 | 实际付款成功的单数 | 未付款/退款不算 |
| 退款数 | 退款成功的单数 | 部分退款也记 1，并在备注写金额 |
| 实际售价（元） | 本周期成交的平均价或逐单价 | 与工作台的“建议售价”分开记 |
| 到手金额（元） | 平台扣费后的到账金额 | 不知道就写 `na`，不要估算 |
| 人工耗时（分钟） | 写文案+交付+答疑的总分钟数 | 估个整数即可，用于算时薪 |
| 交付方式 | `站内文件` / `网盘` / `其他` | 与 b23 结论一致 |
| 备注 | 审核结果、买家常见问题、被拒原因 | 一句话即可 |

**零成交也要记**：成交数写 `0`，并保留**观察期**（建议至少 7 天）再判断“这个品不行”；不要当天没卖出去就下结论。

## 三、一周复盘看这 4 个数字

1. **询单转化率** = 成交数 ÷ 询单数 —— 低说明详情/价格没说服力，不是“没人要”。
2. **单件净利** = 到手金额 − 采购成本 − 售后摊销（用工作台 VALUE 模板里同一口径）。
3. **折算时薪** = 单件净利 ÷（人工耗时 ÷ 60） —— 低于你设定的阈值（默认 ¥30/h）就该考虑提价或换品。
4. **退款率** = 退款数 ÷ 成交数 —— 高说明描述与实物不符，或交付体验有问题。

> 四个数字一起看：只有“询单多 + 转化低”才值得改文案；只有“净利正 + 时薪低”才值得提价或标准化交付；退款率高先修描述与交付，不要靠降价掩盖。

---

## 四、红线（任何时候都不做）

- 不向买家要账号、密码、验证码；不代登录、不代操作对方账号。
- 不在聊天/描述里引导站外交易、不发收款码。
- 不虚构销量/评价，不刷单。
- 买家个人信息（手机号、地址、订单号）**不要粘进本仓库任何文件**；要记就记“已交付”三个字。

> 数据只记不发：这张卡与 `b25/feedback-log.csv` 都只留在本机（不上传、不发群、不进仓库外的任何地方）。
