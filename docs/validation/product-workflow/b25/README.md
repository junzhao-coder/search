# 一周复盘脚本：填完 CSV 就能出结论（不用口算）

> 只读本地文件、纯标准库（不需要装任何包）。脚本给的是**机械建议**，**不等于平台结论，也不代表收益**。

## 三步用起来

**第 1 步：按 FEEDBACK-CARD 填表**
打开 [feedback-log.csv](feedback-log.csv)，照 [b24/FEEDBACK-CARD.md](../b24/FEEDBACK-CARD.md) 的字段口径，一个商品一个观察期记一行（表头固定，别改列名）：

```
日期,单号,渠道,曝光,询单,成交,退款,实际售价,到手,人工耗时分钟,交付方式,备注
```

- `曝光` 对应卡片里的"曝光/浏览"：平台不显示就写 `na`，**不要估算**。
- 没有成交就写 `0`，并保留观察期（建议 ≥7 天）；`na`、空值都会被**跳过**，不会报错。
- 文件里现有的两行是 **synthetic 示例（虚构数据）**，填自己的数据前请先删掉或替换。

**第 2 步：跑脚本**
```bash
python review.py feedback-log.csv
```
想给程序读，就加 `--json`：
```bash
python review.py feedback-log.csv --json
```

**第 3 步：看建议**
屏幕上会先列 4 个数字，再给**一条**建议（四选一：`继续` / `提价` / `换品` / `修描述`），或 `样本不足，保留观察期`：

```
1) 询单转化率      40.0 %   = 成交 ÷ 询单
2) 单件净利        100.0 元  = 单件到手 − 采购 − 售后摊销
3) 折算时薪        20.0 元/小时 = 单件净利 ÷ (人工耗时 ÷ 60)
4) 退款率          25.0 %   = 退款 ÷ 成交
【修描述】依据：退款率 25.0% > 20.0%：先修描述与交付…
```

## 4 个数字怎么算（与 FEEDBACK-CARD 同一口径）

| 指标 | 公式 | 缺失时 |
| --- | --- | --- |
| 询单转化率 | 成交 ÷ 询单 | 询单为 0/na → `na`，不报错 |
| 单件净利 | 单件到手 − 采购成本 − 售后摊销 | 到手为 na → `na` |
| 折算时薪 | 单件净利 ÷ (人工耗时分钟 ÷ 60) | 耗时为 0/na → `na` |
| 退款率 | 退款 ÷ 成交 | 成交为 0 → `na`，并判"样本不足" |

**两条必须知道的假设**（输出里也会打印）：
1. **采购成本、售后摊销**：CSV 没有这两列，默认按 **0** 计；实际有成本请用参数覆盖，例如 `--cost 5 --aftersales 1`。
2. **单件到手** = `到手合计 ÷ 成交合计`；**时薪** = 单件净利 ÷（本行人工耗时 ÷ 60，即把这次观察期的总耗时当作对应这批成交的投入）。

## 阈值可以改

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `--min-conv` | `20` | 转化率低于它 → 先改详情/价格 |
| `--min-hourly` | `30` | 时薪低于它（且净利为正）→ 提价或标准化交付 |
| `--max-refund` | `20` | 退款率高于它 → 先修描述与交付 |

也可以直接改 `review.py` 顶部的常量（`THRESHOLD_MIN_CONVERSION_PCT` 等）。示例：
```bash
python review.py feedback-log.csv --min-hourly 50 --max-refund 15 --cost 6 --aftersales 2
```

## 建议顺序（先看哪条）

1. **净利 ≤ 0** → `换品`（先换品/换货源，别再降价硬撑）。
2. **退款率 > 20%** → `修描述`（写清包含/不包含、交付方式与售后；别用降价掩盖）。
3. **转化率 < 20%（且询单 > 0）** → `修描述`（买家问了没下单，先改详情与价格说明）。
4. **时薪 < 30 元/小时（且净利为正）** → `提价`（提价，或把交付标准化来压耗时）。
5. 都不触发 → `继续`，记录下一个观察期。

## 出错时会怎样

- **某行有非数字**（比如询单写了 `abc`）：脚本会打印 `第 N 行 字段「询单」值「abc」：不是数字，也不是 na`，**退出码 2**，但**仍会打印已解析行的摘要**（不会白跑）。
- **CSV 不存在**：退出码 2，提示文件路径。
- `na` / 空值 / `-` / `无`：当作"没有这个数"，跳过，不报错。

## 边界

- 只算数、不给结论背书：**建议 ≠ 平台结论，≠ 收益保证，≠ 审核结果**。
- 不登录平台、不抓数据、不上传任何东西；CSV 只在你本机。
- 不要在 CSV 里写买家手机号/地址/订单号（卡片红线）；要记就写"已交付"。

## 表头：中文（推荐）与英文别名

`review.py` 会先把表头映射为中文列名再解析；映射表（`HEADER_ALIASES`）：

| 中文列 | 可用英文/别名 |
| --- | --- |
| 日期 | date, day |
| 单号 | workorder_id, workorder, wo, order_id |
| 渠道 | channel, platform |
| 曝光 | impressions, views |
| 询单 | inquiries, leads |
| 成交 | orders, sales, sold |
| 退款 | refunds |
| 实际售价 | actual_price_cny, actual_price, price |
| 到手 | net_received_cny, net_received, received |
| 人工耗时分钟 | manual_minutes, minutes, labor_minutes |
| 交付方式 | delivery |
| 备注 | note, notes, remark |

**可直接复制的中文表头**（配合 `b24/FEEDBACK-CARD.md`）：

```csv
日期,单号,渠道,曝光,询单,成交,退款,实际售价,到手,人工耗时分钟,交付方式,备注
```

### 退出码与报错

- `0`：全部行可解析（`na` 视为缺失，不算错误）。
- `1`：命令行用法错误（缺参数等，由 argparse 返回）。
- `2`：文件不存在、表头缺列、或存在非数字行。此时脚本仍会打印已解析结果摘要，并在末尾给出：
  - `检测到的表头：…`
  - `期望的表头（可直接复制）：…`
  - `修正建议：改成这行表头即可…（英文表头也支持，映射见 README）`
- 若使用了英文别名并被自动映射，非 JSON 输出会打印一行 `表头别名已自动映射：date→日期；…`；`--json` 输出中在 `header.mapped` 下可查。
