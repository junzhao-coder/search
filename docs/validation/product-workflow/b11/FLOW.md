# C3 → 通用：五阶段流程卡（状态机版）

> 目标从「C3 这一个商品」转到「流程本身可复用、可核对」。每阶段按 **进入条件 → 动作 → 产出 → 校验 → 退回条件** 定义，并标注**执行者**与**自动化程度**。
> 自动化口径：**自动**＝系统校验/生成，人只读结果；**半自动**＝系统给结构与校验，人填关键值；**纯人工**＝系统无法判断，必须人做。

## 阶段总览

| # | 阶段 | 执行者 | 自动化 | 当前状态（C3） | 当前状态（提示词包，synthetic） |
| --- | --- | --- | --- | --- | --- |
| 1 | 选品 | 用户 | 半自动 | 已定：学习计划 Excel（b7/b8） | 已定：AI 提示词包（自拟） |
| 2 | 选货源 | 用户 | **纯人工** | 自制 `self:c3-v1`（无外部货源） | 自制 `self:prompt-pack-v1` |
| 3 | 评价价值 | 用户 + 系统 | 半自动 | 已算：VALUE.md（假设参数） | 同模板，换价格/耗时即可 |
| 4 | 写介绍 | 用户 + 系统 | 半自动 | 已定稿：LISTING.md | 已定稿：随 generality 导出 |
| 5 | 上架准备 | 系统校验 + **用户手动发布** | 自动校验 + 纯人工发布 | **6/7 通过，仅 platform 未通过**（导出 409） | synthetic 7/7（导出 200，仅演示） |

## 阶段 1：选品

- **进入条件**：有一批候选（b5 候选 / b7 品类对比）。
- **动作**：看需求信号、竞争密度、可交付性，选一个**自己能做出来**的。
- **产出**：一个具体商品类型 + 交付形态（如「Excel 模板 / .xlsx」）。
- **校验**：能写清「是什么 / 给谁用 / 交付什么」三句话。
- **退回条件**：说不清交付物，或需要他人素材/授权 → 回到候选池。
- **自动化**：半自动（机会页给品类聚合与需求分位；最终选择是人做的）。

## 阶段 2：选货源

- **进入条件**：阶段 1 产出明确的商品类型。
- **动作**：找可商用/可再分发的货源；**或**自制。核对许可三档（可商用/可再分发/可转售）。
- **产出**：`selected_supply_id` + `supply_version` + 许可三档结论 + 样品/交付入口。
- **校验**：三档均 `yes`；样品状态 `verified`（**C3 当前依据是结构自检 17/17，不是真实 Excel 打开**）。
- **退回条件**：许可为 `no`/`unknown`，或拿不到样品 → 回阶段 1 换品。
- **自动化**：**纯人工**（B2 结论：公开货源多为禁止/不明；系统不代找、不代判许可）。

## 阶段 3：评价价值

- **进入条件**：有售价区间假设与耗时估计。
- **动作**：按 `VALUE.md` 的**参数化模板**算单件净利与折算时薪（售价/时薪/耗时/售后预留都可替换）。
- **产出**：净利 + 时薪 + 「做/不做」判断。
- **校验**：单件净利 `< ¥5` 或 时薪 `< ¥30` → 明确写**不值得做**。
- **退回条件**：判定不值得 → 回阶段 1；或改交付方式压缩人工时间再算。
- **自动化**：半自动（表格与公式自动，参数由人填；无真实成交价）。

## 阶段 4：写介绍

- **进入条件**：阶段 3 判定可做。
- **动作**：写标题（3 选 1）、卖点（每条对应具体表/公式）、详情正文、FAQ、交付与售后。
- **产出**：`LISTING.md`（可直接粘贴）+ 工作单的文案字段（`copy_status=final`、`copy_version`）。
- **校验**：无夸大/绝对化/代做/收益承诺；与样品事实一致（5 表/50 公式等）。
- **退回条件**：出现无法由样品证明的表述 → 退回改写。
- **自动化**：半自动（系统存版本号并做关键词级自检；**没有 diff/审批流**）。

## 阶段 5：上架准备

- **进入条件**：阶段 2–4 的字段齐备。
- **动作**：跑七项就绪检查 → 补缺项 → 生成导出包 → **用户手动到平台发布**。
- **产出**：导出包（md/json，买家字段白名单 + 版本戳）+ 发布指引 `PUBLISH-GUIDE.md`。
- **校验**：七项全过才允许导出；`platform_evidence` 为空时**导出 409**；GET 导出零写，记录走 POST。
- **退回条件**：任一硬项未过 → 回对应阶段（platform → 阶段 2/5 人工核验；copy → 阶段 4）。
- **自动化**：**自动校验 + 纯人工发布**（发布永远由用户完成，系统不代发）。

## 流程当前缺口（如实）

| 缺口 | 影响 | 现状 |
| --- | --- | --- |
| 货源检索需人工触发 | 阶段 2 无法自动化，耗时不可控 | 系统只给字段与校验，不检索 |
| 平台条件无法自动核验 | 阶段 5 长期卡在 `platform`（C3 与提示词包均如此） | 需人工填 `platform_evidence` |
| 文案无版本历史/diff | 改文案后只能靠 `copy_version` 记版本，看不到差异 | 仅存版本号 + 关键词自检 |
| 样品核验无自动化 | “已核验”实际是人填的状态 | C3 仅结构自检 17/17 |
| 定价无真实成交数据 | 阶段 3 全部是假设 | 只有 B7 公开样本与 B8 假设三档 |
| 导出记录不去重 | 多次点“记录导出”会多行 | 按显式动作追加（已文档化） |
| 无“发布回填”闭环 | 发布后链接/时间需人工记录 | 见 PUBLISH-GUIDE 的手工记录表 |

## 通用性结论（C3 vs 提示词包）

- **流程通用（系统保证）**：七项检查键与缺项文案、买家字段白名单与内部标记扫描、版本戳与失效判定、GET 零写/POST 记录、CSRF 与同源保护。两个不同交付形态（`.xlsx` 与 `.md`）**走的是同一套检查与导出**，提示词包同样在「仅 platform 缺失」处被 409 挡住。
- **品类相关（必须人工）**：`fmt/version` 的含义（xlsx vs md）、样品核验方式（真实 Excel 打开 vs 文本通读）、平台类目与虚拟交付规则、定价档位。
- 证据：`generality.json`（两单的七项结果、导出状态、买家字段、`fmt` 块）、`exports/prompt_pack_synthetic.{md,json}`、`exports/prompt_pack_blocked.txt`。
