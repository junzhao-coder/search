## 1. 按严重度排列的原稿发现

P1：影响最小闭环正确性或证据/资金口径，建议在对应 S2 契约冻结前消除。P2：实现与独立验收存在歧义，需补齐可复现约定。共 7 组高价值问题；各组只建议最小修订，原成果由原 owner 修改。

### R1 · P1 · 数据库硬约束与负利润、显式未知、无来源运行冲突

**依据：** [所有金额非负及值恰一非空的 CHECK](<../design/CONTRACT.md#L334-L341>)、[反馈净利润字段](<../design/CONTRACT.md#L232-L239>)、[未知规则](<../design/CONTRACT.md#L38-L42>)、[成本值必填约束](<../design/CONTRACT.md#L171-L178>)；[运行来源 FK 与空串默认值](<../design/CONTRACT.md#L303-L306>)、[仅有的 S2 来源种子](<../design/CONTRACT.md#L278>)、[启用外键](<../design/CONTRACT.md#L622>)。对应矩阵 [S2-10](<../design/ACCEPTANCE.md#L49>)、[S2-15](<../design/ACCEPTANCE.md#L54>)、[S2-19](<../design/ACCEPTANCE.md#L58>)。

| 最小输入 | 原稿冲突 | 应有预期 |
| --- | --- | --- |
| 售价 1000 分，逐单成本 1200 分；成交时快照 `predicted_net_per_order_minor=-200` | “所有 `*_minor >= 0`”覆盖净利润字段，与允许亏损的语义相矛盾 | 成本/收入非负，净利润字段允许有符号整数；快照可保存 -200 |
| `role=payment_fee,basis=per_order,value_kind=money,money_minor=null`，另两值也空 | 显式未知成本行与“money 必填 / 恰一值非空”相矛盾 | 定义未知行的合法表示，或明定必需角色缺行即未知；两种实现选一种，零仍存 0 |
| 无来源的 `recompute` 运行，默认 `source_id=''` | `''` 是 FK 值，种子只有 `s_manual`；开启外键后没有对应父记录的默认写入违反关系约束 | 无来源 FK 用 NULL，幂等索引按需用 `COALESCE`；或显式规定合法父记录，避免悬空 FK |

**最小修订：** 将非负 CHECK 限定到原始收入/支出字段，保留有符号净值；补未知项落库规则；统一运行来源的空值与索引口径。三项均需真实迁移/写入测试，本文仅核对声明冲突。

### R2 · P1 · 导入身份未覆盖无原生 ID、无需求组及真实/合成隔离

**依据：** [空值哨兵](<../design/CONTRACT.md#L18>)、[native_id 可空](<../design/CONTRACT.md#L90-L106>)、[真实/合成规则](<../design/CONTRACT.md#L44-L48>)、[需求强键](<../design/CONTRACT.md#L336>)、[可只填基础组的导入](<../design/CONTRACT.md#L406-L421>)、[指纹/去重/版本规则](<../design/CONTRACT.md#L464-L470>)。矩阵 [S2-03/04](<../design/ACCEPTANCE.md#L42-L43>)要求无增殖，但正例 [CSV/JSON](<../design/CONTRACT.md#L483-L511>)均省略原生 ID。

**最小反例与预期：**

| 输入序列（均用合法字段） | 当前规则缺口 | 需要冻结的结果 |
| --- | --- | --- |
| 合成行：同来源、无 `native_id`、同 URL/标题/摘录，原样导入两次 | 若 native_id 存 NULL，SQLite UNIQUE 对 NULL 不作相等防重；若改存空串，则版本身份退化为“来源 + 空串” | 一候选、一信号、一需求证据；第二次跳过而非增殖 |
| 无 ID，两条不同示例 URL，但标题/摘录相同 | 空串路径下强键相同，URL 又未参与身份；可能误跳过第二条；同来源的其他无 ID 内容变化还会被当作同一对象版本 | 两个来源对象保留，可进入疑似重复复核；只给同一 URL 对象追加版本 |
| 仅 `{title:"候选A",data_origin:"synthetic"}`，或只附货源/成本，重导两次 | 没有需求强键；候选没有导入稳定键；批次/行 `client_ref` 的作用域亦未明确 | 有稳定行身份则幂等；身份不足时明确要求补键或进入复核，而非宣称全量重复可跳过 |
| `real` 与 `synthetic` 使用相同来源、native_id、标题、摘录，分别使用真实 URL 与示例 URL | 强键和指纹均不含 `data_origin`；分批存放或界面标签并未消除共享库键碰撞 | 两组独立业务记录与统计；跨 origin 的去重/合并显式拦截 |

**最小修订：** 原生 ID 原样保留；另定义来源对象键（有 ID 用 ID，无 ID 用规范化 URL），内容哈希只做该对象的版本键；强键纳入 `data_origin`。无需求行另用稳定行键，明确批次键与行键的差别。同一需求行重导但追加新货源/成本时，需规定“复用候选并追加子项”还是整行跳过，避免 [可多次导入追加](<../design/CONTRACT.md#L406>)与[业务行数不变](<../design/CONTRACT.md#L466>)冲突。

**依据：** [映射声明](<../design/CONTRACT.md#L409>)、[列清单](<../design/CONTRACT.md#L415-L423>)、[再次声称无第二套命名](<../design/CONTRACT.md#L530-L535>)，对照[需求实体](<../design/CONTRACT.md#L90-L100>)和[货源实体](<../design/CONTRACT.md#L141-L158>)。

| `demand_engagement` | `engagement` | `engagement_json`，需定义允许结构/编码 |

**最小反例：** 原稿 CSV 正例本身包含上述别名，不能由声明的映射直接填充必需实体字段；`supply_evidence_url` 派生的证据还缺明确的 `excerpt`、`fact_kind` 赋值规则，而[证据实体](<../design/CONTRACT.md#L123-L127>)要求二者非空。

**预期/最小修订：** 保留现有列名，增加小型显式映射/默认值表及派生证据必需输入；无需另建通用映射框架。S2-03 应固定每个实体的字段断言及计数，不只写“与预期一致”。许可 URL 只有入口、尚无许可摘录时，保留货源候选与缺口，不把 URL 自动当成已核对许可结论。

### R4 · P1 · 四门槛仅检查引用有效，尚未阻挡结构化业务反证/缺项

**依据：** [核验记录字段](<../design/CONTRACT.md#L198-L204>)、[testable 派生条件](<../design/CONTRACT.md#L384-L386>)、[唯一具体核验请求约束](<../design/CONTRACT.md#L590-L597>)，对照[产品 D05/D08](<../../PRODUCT.md#L29-L32>)及[可测试定义](<../../PRODUCT.md#L46>)。

**最小反例：** 同一候选下四条未失效、类型各自匹配的证据；需求记录为 `seller_promo`；货源 `resale_allowed=no,sample_checked=none`；成本项全缺。逐项提交 `status=verified` 与对应证据 ID。四次请求满足原稿唯一列明的同候选/类型/有效期条件，状态表随后导出 `testable`，但商品仍缺适用分发、抽检与完整成本依据。

**预期：** 来源宣传/资源目录的“verified”不自动成为需求或经营资格；货源结构化禁止条件和关键缺项应挡入池。成本核验与必要成本角色/假设完整性关联；平台核验说明具体销售平台与商品适用条件。证据反证或缺项时保持待核验/失败状态并列出原因。

**最小修订：** 给四门槛各加最少的可复查核验前提与 422 错误原因，明确 `user` / `system_rule` 的边界。货源抽检可为有记录的 `partial`，但需范围、结果和未核验部分。无需让模型自动判定许可。A 的[索引状态图例](<../research/SAMPLES.json#L12-L27>)只核到许可/访问，且[字体样例](<../research/SAMPLES.json#L193-L214>)含“单独售卖禁止”和未验货，正是需保留反证的真实目录例子。

### R5 · P1 · 逐单采购固定映为一次性，货源计价与利润情景未关联

**依据：** [货源 price_basis](<../design/CONTRACT.md#L145-L148>)、[成本 basis/period](<../design/CONTRACT.md#L170-L179>)、[procurement_cost 固定 one_time](<../design/CONTRACT.md#L429-L435>)、[V19 仅检查金额不等](<../design/CONTRACT.md#L459>)、[逐单利润公式](<../design/CONTRACT.md#L617>)，对照[产品采购计入利润](<../../PRODUCT.md#L70-L76>)及[完整上游费用模型](<../../DEVELOPMENT_PLAN.md#L111>)。

**最小演算：** `sale_price="10.00",supply_price="2.00",supply_price_basis=per_unit,procurement_cost="2.00"`，其余逐单费用与人工均显式为零。正确逐单利润是 `1000-200=800` 分。原稿却将 200 分归入一次性；若缺逐单采购角色按零处理，返回 1000 分；若按未知处理，则本来已给出价格的情景仍不完整。两种路径都未表达实际逐单费用，V19 因两价相等也没有提示。

**预期/最小修订：** 用显式采购 basis 列，或在有且仅有明确适用货源时按 `per_unit→per_order`、`one_time→one_time`、`subscription→recurring` 映射；未知计价基础保持未知。成本需注明采用哪个货源/情景，同一候选多个价格不得混作一套成本。

一次性费用单列本身可接受，问题是逐单费用被误归类；S4 再补销量/期间假设的总体收益与周期换算。例如一次性 2000 分、每单贡献 1000 分、两单的项目收益为 0；订阅 12000 分/年按十二月分摊为 1000 分/月。现[响应示例及规则](<../design/CONTRACT.md#L605-L617>)有 `recurring_monthly_total`，但尚缺季度/年度归一与余分处理规则，属于 S4 实现前细化，不要求 S1 建摊销引擎。

### R6 · P1 · 反馈缺退款归属、结算写入口及实际核算单位

**依据：** [反馈实体](<../design/CONTRACT.md#L223-L242>)、[更新白名单](<../design/CONTRACT.md#L351>)、[端点表只含新增反馈](<../design/CONTRACT.md#L556-L584>)；矩阵 [S2-19](<../design/ACCEPTANCE.md#L58>)、[S5-06](<../design/ACCEPTANCE.md#L91>)要求 pending→settled 并核算实际值。

**最小反例：** 同候选成交 A=5000 分、B=15000 分，随后退款 5000 分。现字段只关联候选，未关联哪笔成交：它既可能全退 A（A 净收入 0），也可能部分退 B（B 净收入 10000）；据此没有唯一的“该笔实际每单利润”。已有 `refund(pending,client_ref=r1)` 时，用原键提交 settled 按[幂等规则](<../design/CONTRACT.md#L56>)应为不同载荷 409；换键则新增另一笔，仍没有更新原退款的明确路由。

**预期/最小修订：** 最小方案是增加成交/退款关联和明确的反馈结算 PATCH，区分待结清与实际已退金额；或首版显式冻结为经营试验窗口聚合，并注明窗口/单数，避免声称订单级精度。`manual_time` 还需明确分钟、实际人工计价与金额的输入单位，现 `quantity` 只称“数量”。实际值由服务端按关联记录核算；未知实际费用保留未知，预测快照写入后保持不变。

**结算断言：** 已知实际成本全零，单笔收入 10000 分、预估退款预留 500 分；实际全退 10000 分结清后实际利润为 0，而非 -500；重复结算不再扣款，原预测快照仍为 9500 分。此断言尚未运行。

### R7 · P2 · 写接口缺最小请求契约与持久幂等落点，首个成本项也缺入口

**依据：** [全局幂等](<../design/CONTRACT.md#L54-L56>)、[实际带 client_ref 的实体](<../design/CONTRACT.md#L239>)和[批次/唯一键](<../design/CONTRACT.md#L315-L340>)，对照[证据、货源、成本修正、门槛、合并、草稿端点](<../design/CONTRACT.md#L565-L577>)。除门槛外只列用途，没有各写接口必需输入、只读字段和明确返回结构。

**最小反例：** 用同 `client_ref` 生成草稿，重启再重放；端点承诺原记录，但 draft 没有该键，亦未定义公共幂等回执/载荷摘要。相同键不同 body 应 409 的对比落点也未冻结，矩阵 [S2-20](<../design/ACCEPTANCE.md#L59>)没有重启条件。另一条窄链路：先导入无成本候选，再补第一个支付成本；唯一成本写端点是 `supersede/{id}`，此时没有旧成本 ID 可供修正，多次导入补子项又受 R2 整行跳过规则影响。

**预期/最小修订：** 给写端点添加精简请求/响应与可写字段表，复用实体定义；明确必需关联、枚举和 400/404/409/422 的边界。选择一种可落库的最小幂等方案（实体键+载荷摘要，或单张回执表），明确作用域与事务，重启后仍复用原结果。补首次成本追加路径及选定货源/情景输入。无需通用服务层、消息队列或接口生成系统。
